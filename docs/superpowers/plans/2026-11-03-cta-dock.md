# CTA Tracker Dock Firmware Plan (Plan 2 of 4)

> **Reference plan, not a script.** This lays out milestones, module boundaries, and the decisions made so far. Expect it to change as the hardware and libraries teach us things. When the code shows a better way, take it, say so, and update this file in the same commit. The spec is the contract. Execute natively, one milestone at a time, following `docs/Agent-Workflow.md`.
>
> **The UI is subject to change, and likely will.** Screen layouts, sizes, colors, fonts, copy, and pet art here are starting points, not final designs. Build them so they're easy to change; don't treat a UI detail in this plan as fixed.

## Status: v1 built (2026-11-12)

Dock firmware v1 implements the approved UI mockup (`docs/ideas/2026-11-11-dock-ui-mockup.html`, Leo, 2026-11-12) with live data over Wi-Fi and the LED rows. That covers milestones 1 and 3–6, part of 2 (the picks in NVS; no `DeviceConfig` yet), and the pet of milestone 8 (no two-finger debug gesture; serial "m" cycles the moods). BLE (milestone 7) and the soak (milestone 9) remain. What changed from the plan below:

- **No LVGL.** The dock draws with the handheld's `gfx2d` canvas (Nunito atlases, pixel plates, `pet::` sprites), now shared in `firmware/lib/gfx` with the card theme and pieces (`card_theme.*`). Two new canvas calls back the map: `seg` (crisp block lines, the mockup's Bresenham worked out per step, so a band only visits its own steps) and `dot`. `Canvas::strided` draws in any memory layout. The mockup needed no font sizes the atlases lacked.
- **Frames:** the 480 × 800 portrait screen is drawn in 32-row bands in internal RAM, already in the landscape panel's order (`bands.*`), and copied into the hidden one of two PSRAM frame buffers (only bands that changed since that buffer last got them). The panel switches buffers when it starts its next frame, and the loop waits for the driver's frame-buffer-complete event before drawing into the old one.
  - **Shaking and tearing (Leo, 2026-11-12):** these came from the panel's bounce-buffer refills running late, not from the buffer swap. A refill that misses its turn leaves the driver filling the bounce buffer the DMA is already sending, for good (with `CONFIG_LCD_RGB_RESTART_IN_VSYNC` its count of DMA EOFs never resets). That shows as stale slivers at the start of every few lines, which in portrait is the status strip, and as the image shifting sideways. Refills ran late during Wi-Fi joins, TLS and map redraws, and always during flash writes: while flash is written the cache is off, so the refill can't read the PSRAM frame buffers.
    - Tried on the stock core: the panel's interrupts on core 1, bigger bounce buffers, 12–16 MHz, Wi-Fi not writing to flash on each join, restarting the panel after every flash write and on any late frame, and no bounce buffers at all (worse: it glitched even with nothing drawing).
    - **The fix: Espressif's prebuilt "high_perf" Arduino SDK** (esp-arduino-libs/arduino-esp32-sdk), its documented cure for RGB drift on the S3 (ESP32_Display_Panel, `docs/envs/use_with_arduino.md`, "Solution for screen drift issue"). It turns on XIP from PSRAM, so code keeps running and the refill keeps reading while flash is written, and 64-byte data cache lines. Its libraries must match the core, and 3.2.0 is the newest, so `firmware/dock/platformio.ini` pins pioarduino 54.03.20 (arduino-esp32 3.2.0, IDF 5.4.1) with `esp32-3.2.0-h` in its own `core_dir` (`~/.platformio-dock`), where it can't replace the handheld's core. The boot log confirms it (`display: SDK ..., XIP from PSRAM on, data cache line 64 B`).
    - The timing is T0: 14 MHz, falling edge, porches 4/8/8, 20-line bounce buffers (about 1.2 ms per refill). Espressif's board file for this panel uses 16 MHz and 10 lines (T1), which still glitched briefly once in Leo's test; the drift guide's next step is bigger bounce buffers. Leo's filmed test on T0 (2026-11-12): clean, with no late frames or panel restarts, across the map, three real Wi-Fi drops and 4 pick writes.
    - The dock still writes flash only when a value really changes (picks; the location only when it moves over 1 km, `cta::geoWorthSaving`), and still restarts the panel if a frame ever comes late, as a backstop.
  - **Core 3.2.0 workarounds** (all fixed in 3.3): its RMT setup leaves `allow_pd` uninitialised, so the LEDs drive the RMT themselves (below); its TLS `stop()` wipes the certificate bundle's hook, so `Tls::stop` attaches it again; its `String` keeps a length in 16 bits while growing, which mangled bodies over 64 KB (route 22's patterns are 70 KB), so response bodies are read into a String reserved to full size up front (`readBody`). It also logs a harmless `setSocketOption(): fail on 0, errno: 9` on each request.
  - **Cost on the high_perf SDK:** frames take about 65–85 ms, and internal RAM bottoms out at about 105 KB.
  - A frame is drawn on new data, a touch, the minute, or the half-second bob.
- **Network:** `net.*` follows the handheld's live build (its DNS lookup, one HTTPS connection kept open for the train requests, NTP by address with the train API's `Date` header as fallback) on the dock's own WPA2-Personal network from `DOCK_WIFI_SSID` / `DOCK_WIFI_PASS`. Big JSON documents (bus patterns, picker lists) go to PSRAM through `cta::setJsonHeap`.
- **Status logic:** `dock_status.*` (in the shared library, native-tested) counts arrivals down from the fetch and decides LED 7's due state, the greyed cards, the mood, and Trackie's reason. The location lookup's timing (`geoLookupDue`) and the Wi-Fi back-off (`wifiRetryDelayMs`: 2 s, then 15 s doubling to 5 min) are in `schedule.h`, and the tap, long-press and swipe rules in `gesture.h`, all with native tests. Picker lists carry the route and direction they answer, so a reply to an earlier choice reads as still loading.
- **Branch rows:** `trainRowFor` starts Green's Cottage Grove and Ashland/63rd branch rows, and the Loop-bound Purple Express row, with the last stops of the run that feeds them (a small table in `approach.cpp`).
- **Picks:** `cta::PickedStop` with a JSON codec (`picks.*`), saved in NVS (`store.*`). The defaults are Red at Belmont to 95th (30256), Brown at Diversey to the Loop (30104), and the 22 at Clark & Belmont southbound (1828).
- **Map mode** (new in the mockup): `map_frame.*` frames the 3 approach zones; vehicles sit between the stops of their lit LEDs (`vehicleAt`, `vehiclesFor`). The L comes from `train_map.cpp`, generated by `tools/map_build.py` from `data/train_shapes.json` (platform positions from `data/stops.json`). Bus lines come from the cached `getpatterns` points (`busPatternPath`).
- **LEDs:** GPIO 6 (the header pin labelled "AD"). `dock_leds.*` gives the colors: chain index 7r + i, LED 7 (the picked stop) at the right end, breathing while due, rows dark after `kLedStaleSec`, everything off at night, every channel capped by `LED_MAX_BRIGHTNESS` (96). Driven on the RMT directly (a zeroed channel config and a bytes encoder with WS2812B timing, `leds.cpp`) from its own task on core 0 through a one-frame mailbox. That keeps the RMT refill interrupt away from the panel's refills on core 1.

**Files:** `firmware/dock/{platformio.ini, include/pins.h, src/{main, display, bands, dock_ui, net, leds, store}.*, tools/{preview.cpp, frame_grab.py}}`; shared: `firmware/lib/gfx`, and in `firmware/lib/cta`: `approach`, `bus_picker`, `dock_leds`, `dock_status`, `map_frame`, `picks`, `schedule.h`, `json_heap`, `train_map` (+ `train_map_find.cpp`), plus additions to `urls` (picker, ipapi.co), `alerts_weather` (`parseGeoIp`), and `cta_config` (`kGeoLookupSec`). Tests: `test_approach`, `test_dock`, `test_gfx`, plus additions to `test_urls` and `test_alerts_weather`. Laptop preview: `firmware/dock/tools/preview.cpp`, which also checks that the band path matches a plain frame pixel for pixel.

**Serial (115200, UART port):** `s` next screen, `m` cycle moods, `p` print picks, `d` default picks, `x` swap sections 1 and 2 (a real flash write), `h` stops screen, `0`–`6` tearing diagnostics (normal, freeze, test pattern, Wi-Fi off, single buffer, next panel timing T0–T5, panel restart off/on), `A`–`Z` a step letter on screen, `l` LED colors, `w` check the dock's network is on the air (never prints a name), `g` time the drawing, `f` grab the screen (`tools/frame_grab.py`). Touches log their start and end points. `scan:` lines appear only when the panel's refills ran late.

## Module map (the original plan; see the status above for what was built)

```
firmware/dock/platformio.ini        board settings from toolchain notes; lib_extra_dirs = ../lib; -I.. for secrets.h
firmware/dock/include/pins.h        LED_DATA_PIN (set when wired)
firmware/dock/src/main.cpp          setup/loop wiring only
firmware/dock/src/display.*         panel + touch + LVGL init (ported from the Waveshare demo), portrait rotation
firmware/dock/src/ui_main.*         status strip + 3 stop sections; renders from a DockState snapshot
firmware/dock/src/ui_picker.*       Train/Bus → line/route → direction → stop flow
firmware/dock/src/pet_view.*        LVGL canvas in the status strip, fed by pet::renderSprite at 2×
firmware/dock/src/leds.*            LED rows over the RMT: mask + color + pulse + brightness cap
firmware/dock/src/net.*             Wi-Fi connect/backoff, NTP + time zone
firmware/dock/src/poller.*          what to fetch and when; writes into DockState
firmware/dock/src/rows.*            builds and caches the 3 ApproachRows when stops change
firmware/dock/src/store.*           NVS (Preferences): Wi-Fi, DeviceConfig
firmware/dock/src/ble_server.*      NimBLE service: info, wifi, config
firmware/lib/cta/src/device_config.*  NEW shared: DeviceConfig + JSON codec (also used by the handheld)
firmware/lib/cta/src/scheduler.*      NEW shared: pure "what's due now" logic, natively testable
```

**Rule of thumb:** anything that's pure logic goes into `firmware/lib/cta` with a native test. Device files stay thin glue around LVGL, NeoPixels, NVS, Wi-Fi, and BLE.

## Milestones

Each milestone ends with something you can see working, plus a review per the workflow. Hardware checks are Leo's.

1. **Screen up.** Port the display init from the toolchain spike into `display.*`, in portrait, with LVGL showing a placeholder layout (strip + 3 empty sections reading "Tap to pick a stop"). *Check (Leo):* the layout renders upright, and a touch in each section logs its index.
2. **Config and storage.** `device_config` and `scheduler` in the shared lib with native tests; `store.*` loads and saves `DeviceConfig` and Wi-Fi in NVS. *Check:* native tests pass; a config set over serial (debug command) survives a reboot.
3. **Online.** `net.*` joins the saved Wi-Fi, retries with backoff, sets time over NTP with `kTz`, and shows the Wi-Fi icon state. With no saved Wi-Fi, the screen shows "Open the CTA app to set up Wi-Fi". With an empty key in `secrets.h`, it shows "No API key". During night hours the screen dims (spec §7.4).
4. **Live arrivals.** `poller.*` fetches, for each picked stop:
   - train: `ttarrivals` by platform ID
   - bus: `getpredictions` for all picked bus stops in one call, filtered by each stop's route
   - alerts every 5 min for the picked routes, which set `StopRecord.alert`
   - weather every 15 min at the dock's own location: ipapi.co at boot and once a day, cached in NVS; with no location yet, the weather icon is hidden (spec §7.5)

   `ui_main` renders the 3 sections: color bar, name → direction, next 3 arrivals, and Delayed/Sched/⚠ badges. When offline, sections grey out with "updated N min ago". *Check:* the dock shows live data for 3 hardcoded stops set through the serial debug command.
5. **LED rows.**
   - When stops change, `rows.*` builds rows: trains from `kTrainLines` (use the line of the same route that holds the platform ID past its `lead`; the row is the up-to-6 stops before it in that line, lead-in included), buses from `getpatterns` (body fetched into a PSRAM buffer, rows cached until the stop changes).
   - The poller adds `ttpositions` per picked train line and `getvehicles` for picked bus routes (one call, up to 10 routes).
   - `leds.*` applies the masks in the line color (buses `0x565A5C`), pulses LED 7 when that stop's next live arrival is ≤ `kHypedMaxMin`, caps brightness at `LED_MAX_BRIGHTNESS` scaled by `cfg.led`, turns rows off when their data is older than `kLedStaleSec`, and turns everything off at night.

   *Check (Leo):* the LEDs track a real train approaching a stop over a few minutes.
6. **Stop picker.**
   - Long-press a section to open the picker.
   - Trains: line list → direction (`dirLabel`) → station list, all from `kTrainLines` (skip each line's first `lead` stops, which are lead-in, not picks; a (line, direction) can span several sequences, so merge their stations; Plan 1 Task 10 rulings).
   - Buses: route list from `getroutes`, then `getdirections`, then `getstops`, fetched live, with a "Loading…" state and an error message on failure.
   - Saving writes NVS, rebuilds that row, and triggers an immediate poll.
7. **BLE server.**
   - NimBLE service with `info` (read), `wifi` (encrypted write, slot 0 only), and `config` (read/write, including stops).
   - Advertises as `CTA-Dock-xxxx`.
   - Shows the passkey full-screen during pairing.
   - A `config` write applies through `applyConfigJson`, saves, and refreshes the UI and rows. The most recent pick wins, whether it came from the app or the dock.

   *Check (Leo):* pair from the iPhone with LightBlue, write a `config` with a new stop, and watch the section change.
8. **Pet.** `pet_view.*` shows `deviceMood` over the 3 stops (all 3 are Hyped-eligible) at 64 px, with the weather accessory and the palette from `cfg.petColors`. A two-finger long-press on the pet cycles all states (debug, spec §6.3). The animation runs at a few frames per second.
9. **Soak and demo check.** Run 2 hours on Wi-Fi with the app connected now and then. Log the minimum free heap every 5 min to serial. Walk the dock items of the spec §1 demo checklist (items 1–4 and 6 for the dock).

## Decisions so far

- **LED_DATA_PIN** is GPIO 6 (Leo, 2026-11-12).
- **NeoPixel driver:** Adafruit_NeoPixel (RMT on the S3) to start. If the RGB LCD's DMA causes LED glitches, try FastLED's RMT driver, or update LEDs only between LVGL flushes.
- **Bus patterns** are large: fetch them into PSRAM with `ps_malloc`, parse once, keep only the rows.
- **One UI state object** (`DockState`: 3 `StopRecord`s, 3 masks, Wi-Fi state, mood, accessory) is written by the poller and read by the UI. All writes happen on the loop task, so no locks are needed unless BLE callbacks write to it; BLE callbacks only queue work for the loop.
- **Picked train stops are platform IDs** (`3xxxx`), so `ttarrivals` returns one direction.
