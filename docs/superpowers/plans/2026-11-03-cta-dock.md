# CTA Tracker Dock Firmware Plan (Plan 2 of 4)

> **Reference plan, not a script.** This lays out milestones, module boundaries, and the decisions made so far. Expect it to change as the hardware and libraries teach us things. When the code shows a better way, take it, say so, and update this file in the same commit. The spec is the contract. Execute natively, one milestone at a time, following `docs/Agent-Workflow.md`.

**Goal:** Dock firmware for the Waveshare 4.3" board: a portrait screen with the pet and 3 stop sections, 3 LED approach rows, an on-screen stop picker, and a BLE server so the app can set Wi-Fi, stops, pet, and settings.

**Spec:** `docs/superpowers/specs/2026-11-03-cta-tracker-design.md` (sections 3, 4, 6, 7, 10, 12)

**Depends on Plan 1:**
- `docs/notes/toolchain.md`: platform, core, library versions, board settings, CA-bundle snippet, LVGL version
- `cta` library: `StopRecord`, `parseTrainArrivals`, `parseTrainPositions`, `parseBusPredictions`, `parseBusVehicles`, `parseAlertRoutes`, `parseWeather`, `accessoryFor`, `stopMood`, `deviceMood`, `buildTrainRow`, `buildBusRows`, `litMaskTrains`, `litMaskBuses`, URL builders, `lineColor`, `inNightHours`, `cta_config.h`, `ble_ids.h`, `kTrainLines`
- `cta_net`: `ctaGet`
- `pet` library: `renderSprite`, `petStateFor`, `kPetAnims`, overlays, `kDefaultPalette565`


**Rule of thumb:** anything that's pure logic goes into `firmware/lib/cta` with a native test. Device files stay thin glue around LVGL, NeoPixels, NVS, Wi-Fi, and BLE.

## Shared additions (native-tested)

**`device_config.h`**

```cpp
struct PickedStop { cta::Kind type; char route[8]; char dir[25]; char id[8]; char name[25]; };  // id[0]=='\0' → empty
struct DeviceConfig {
  PickedStop stops[3];                 // dock only
  char petName[17]; uint32_t petColors[2];        // body, stripe (palette slots 2, 3)
  uint8_t screen; uint8_t led;         // 0–100 %
  int16_t nightStart, nightEnd;        // minutes of day; defaults kNightStartMin / kNightEndMin
};
bool applyConfigJson(const char* json, size_t len, DeviceConfig& cfg);  // partial update: only keys present change
size_t encodeConfigJson(const DeviceConfig& cfg, bool includeStops, char* buf, size_t cap);
size_t encodeInfoJson(const char* type, const char* fw, int battery, bool charging, bool wifiUp, const char* ssid, uint32_t lastUpdate, char* buf, size_t cap);
bool decodeWifiJson(const char* json, size_t len, uint8_t& slot, char* ssid, size_t ssidCap, char* pass, size_t passCap);
```

Tests to include:
- A partial write (`{"pet":{"name":"Rosie"}}`) leaves the stops untouched.
- An out-of-range slot or brightness is rejected.
- `config` JSON round-trips.
- An oversized password is rejected rather than truncated.

**Geolocation (in `alerts_weather.*`)**: `bool geoIpUrl(char* buf, size_t cap)` → `https://ipapi.co/json/`; `bool parseGeoIp(const char* json, size_t len, double& lat, double& lon)`. Fixtures: `fixtures/cta/geoip.json` (`latitude` 41.8781, `longitude` −87.6298) and `geoip_error.json` (`{"error": true, "reason": "RateLimited"}` → false).

**`scheduler.h`**: one small struct per job (`intervalSec`, `lastRun`), with `isDue(now, slowMode)`. Slow mode (night hours) stretches every job to `kSlowPollSec`. Test that night hours switch cadence and that the first call is always due.

## Milestones

Each milestone ends with something you can see working, plus a review per the workflow. Hardware checks are Leo's.

1. **Screen up.** Port the display init from the toolchain spike into `display.*`, in portrait, with LVGL showing a placeholder layout (strip + 3 empty sections reading "Tap to pick a stop"). *Check (Leo):* the layout renders upright, and a touch in each section logs its index.
2. **Config and storage.** `device_config` and `scheduler` in the shared lib with native tests; `store.*` loads and saves `DeviceConfig` and Wi-Fi in NVS. *Check:* native tests pass; a config set over serial (debug command) survives a reboot.
3. **Online.** `net.*` joins the saved Wi-Fi, retries with backoff, sets time over NTP with `kTz`, and shows the Wi-Fi icon state. With no saved Wi-Fi, the screen shows "Open the CTA app to set up Wi-Fi". With an empty key in `secrets.h`, it shows "No API key". During night hours the screen dims (spec §7.4).
4. **Live arrivals.** `poller.*` fetches, for each picked stop:
   - train: `ttarrivals` by platform ID
   - bus: `getpredictions` for all picked bus stops in one call, filtered by each stop's route
   - alerts every 5 min for the picked routes, which set `StopRecord.alert`
   - weather every 15 min at the dock's own location: ipapi.co at boot and once a day, cached in NVS; with no location yet, the weather icon is hidden (spec §7.5)

   `ui_main` renders the 3 sections: color bar, name → direction, next 3 arrivals, and Delayed/Sched/⚠ badges. When offline, sections grey out with "updated N min ago". *Check:* the dock shows live data for 3 hardcoded stops set through the serial debug command.
5. **LED rows.**
   - When stops change, `rows.*` builds rows: trains from `kTrainLines` (find the line and direction containing the platform ID), buses from `getpatterns` (body fetched into a PSRAM buffer, rows cached until the stop changes).
   - The poller adds `ttpositions` per picked train line and `getvehicles` for picked bus routes (one call, up to 10 routes).
   - `leds.*` applies the masks in the line color (buses `0x565A5C`), pulses LED 7 when that stop's next live arrival is ≤ `kHypedMaxMin`, caps brightness at `LED_MAX_BRIGHTNESS` scaled by `cfg.led`, turns rows off when their data is older than `kLedStaleSec`, and turns everything off at night.

   *Check (Leo):* the LEDs track a real train approaching a stop over a few minutes.
6. **Stop picker.**
   - Long-press a section to open the picker.
   - Trains: line list → direction (`dirLabel`) → station list, all from `kTrainLines`.
   - Buses: route list from `getroutes`, then `getdirections`, then `getstops`, fetched live, with a "Loading…" state and an error message on failure.
   - Saving writes NVS, rebuilds that row, and triggers an immediate poll.
7. **BLE server.**
   - NimBLE service with `info` (read), `wifi` (encrypted write, slot 0 only), and `config` (read/write, including stops).
   - Advertises as `CTA-Dock-xxxx`.
   - Shows the passkey full-screen during pairing.
   - A `config` write applies through `applyConfigJson`, saves, and refreshes the UI and rows. The most recent pick wins, whether it came from the app or the dock.

   *Check (Leo):* pair from the iPhone with LightBlue, write a `config` with a new stop, and watch the section change.
8. **Pet.** `pet_view.*` shows `deviceMood` over the 3 stops (all 3 are Hyped-eligible) at 64 px, with the weather accessory and the palette from `cfg.petColors`. A two-finger long-press on the pet cycles all states (debug, spec §6.3). The animation runs at a few frames per second.
9. **Soak and demo check.** Run 2 hours on Wi-Fi with the app connected now and then. Log the minimum free heap every 5 min to serial. Walk the dock items of the spec §1 demo checklist (items 1–4 and 6 for the dock).

## Decisions so far

- **NeoPixel driver:** Adafruit_NeoPixel (RMT on the S3) to start. If the RGB LCD's DMA causes LED glitches, try FastLED's RMT driver, or update LEDs only between LVGL flushes.
- **Bus patterns** are large: fetch them into PSRAM with `ps_malloc`, parse once, keep only the rows.
- **One UI state object** (`DockState`: 3 `StopRecord`s, 3 masks, Wi-Fi state, mood, accessory) is written by the poller and read by the UI. All writes happen on the loop task, so no locks are needed unless BLE callbacks write to it; BLE callbacks only queue work for the loop.
- **Picked train stops are platform IDs** (`3xxxx`), so `ttarrivals` returns one direction.

## Open questions (expect answers to change this plan)

- **Request budget:** confirm against the daily limits in the key emails, and adjust `kDockPollSec` or bus cadence if needed.
- **LVGL 8.4 vs 9** on this board, per the toolchain notes.
- **Picker usability** for bus routes with 100+ stops: a plain scrolling list may be enough; add letter jump or search only if it's painful.
- **Free GPIO** for `LED_DATA_PIN`: hardware, Leo decides.
